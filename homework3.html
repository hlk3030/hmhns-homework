需求来源与追溯规则

每一条系统需求都必须能顺着一条链走回去：患者的某句话 → 某条业务约束 → 某条接口或安全需求 → 某个架构组件。走不通的条目，要么是需求写错了，要么是实现漏了。

诉求StR / BR→ 约束BC-1 — BC-4→ 接口与安全IR / SSR→ 组件SW / HW
一条完整示例

患者"可随时关闭辅助、退回纯自主"（StR-02）→ BC-2 控制权可切换、人有最高否决权 → IR-06 保留独立物理急停、不依赖软件栈 → SSR-6 急停硬线直达切断回路 → 组件 急停按钮与硬线（HW-20）。

三类需求的写法

功能需求写"系统应做什么"；性能需求写"做到什么程度、多久之内"；接口需求写"跟谁交换什么、断了怎么办"。安全需求不写动作，写"不许发生什么、失效时退到哪"。

02

性能需求PR-1 — PR-7

性能需求是这套系统最容易写虚的部分，因此每条都给出可测的口径：从哪一刻算到哪一刻、用什么信号测、允许多大偏差。

编号指标要求与口径验证方法
PR-1意图识别延迟端到端 ≤200 ms：从肌电信号进入决策单元算起，到输出关节指令为止，不含机械动作时间。注入已知动作信号，测时间戳差
PR-2助力分级与分辨率0—5 级可分，力矩分辨率 ≤1 N·m，能分辨患者发力变化。阶梯加载测试
PR-3安全保护响应≤50 ms：从越界检出到切断增强输出，含硬件限幅动作。越界注入 + 示波器测切断时刻
PR-4助力跟随质量助力与主动发力同相位，相位滞后 ≤60 ms，力矩误差 ≤15%，无过冲与牵拉。肌电包络与输出力矩比对
PR-5连续工作能力连续工作 8 h 无单点失效；电量、温升、信号漂移、机械磨损任一项超标即判不通过。整机连续运行 + 四项监测
PR-6单次训练时长单次训练 ≤30 min，超出即提示休息；剩余时长估算误差在允许范围。计时与电量联动测试
PR-7冗余通道切换主通道断开时毫秒级切换（≤20 ms），切换期间输出保持安全默认值。断通道注入测试

200 ms 与 50 ms 是两个不同的预算：前者是"从想到做"的识别链路，允许预测补偿参与；后者是"从不该发生的发生到被切断"的保护链路，不允许任何软件排队。

04

安全需求SSR-1 — SSR-12

安全需求全部写成约束与退路：不许怎样、失效时退到哪、谁能把它拉回来。每条都指到一个具体组件，而不是"系统应保证安全"。

编号安全需求落点组件
SSR-1执行器力矩、角度、电流必须有硬件限幅，越限即切断助力输出，不依赖软件判定。HW-10 / HW-14 / SW-08
SSR-2意图置信度低于阈值时不得输出主动助力，应转有限辅助或纯自主。SW-04 / SW-09
SSR-3反馈超时或丢失时冻结输出并降级，不得以最后一次值继续外推。SS-12 / SW-09
SSR-4安全监护应独立供电、独立传感、独立时钟、独立软件，并周期自检。SS-17 — SS-19
SSR-5主通道失效时切备份，切换期间输出先回安全默认值再恢复。HW-13 / SW-07
SSR-6物理急停应经硬线直达切断回路，不经软件、操作系统与无线链路。HW-20
SSR-7断电或掉电时执行器卸载，无源机械结构保证人不摔倒、关节不锁死。HW-08 / HW-09
SSR-8电极接触阻抗异常或脱落时立即停止增强输出，并显性告警到具体通道。SS-01 / SS-18
SSR-9训练中体征越界时先限制增强，未恢复即强制停机。SS-17 / SS-19
SSR-10人工否决权最高：患者、治疗师、家属的停止请求优先于任何自动决策。SW-09 / HW-20
SSR-11共因隔离：监护不得与主链路共用供电、传感器、时钟或软件。SS-17 — SS-19 独立域
SSR-12分级降级只往少帮忙的方向退：提示 → 限制助力 → 强制停机 → 纯自主；恢复需人工确认。SW-09 / SS-19
05

六系统双通道功能架构

架构不是在人体之外另建一条链路，而是给每个功能系统配一条人工通道：生物通道在，机器只补差；生物通道弱，人工通道顶到基础功能为止。

06

四层安全架构

安全不是一道门，而是四道互相独立的门：人在环、决策层、执行层、独立旁路。任何一层失效，下一层仍然能把输出降下来。

失效默认安全

任一模块失效，系统回到无增强状态：执行器卸载、保持安全位姿。断电时由无源机械结构先保证人不摔倒，再谈记录与告警。

共因隔离

监护不与主链路共用供电、传感器、时钟与软件。共用任何一项，都可能被同一个原因同时带走"出力"和"刹车"。

07

STPA 风险分析与派生约束

零件都没坏，人也可能受伤：问题出在控制给错了动作，或该给的动作没给。按损失 → 危险状态 → 不安全控制动作 → 安全约束的顺序往下推。

层次内容说明
损失 L人身伤害、体征失稳、失控误动作、数据泄露四类损失对应四条不同的防护线，不合并处理。
危险状态 H执行器超限、错误意图、反馈失控危险状态由控制动作引起，而不是由部件故障引起。
不安全控制动作 UCA给了不该给的、该给没给、顺序错、停得过早四类失效覆盖全部控制动作，逐条对照六个系统。
安全约束每条 UCA 反过来写成约束，落到具体组件约束必须能测，不能只写"加强管理"。

四个典型不安全控制动作

编号控制动作不安全情形与风险派生约束
UCA-1决策 · 输出主动助力给了不该给的：识别置信度不足仍输出助力，患者被带向错误轨迹。置信度低于阈值转有限辅助或纯自主（SSR-2）。
UCA-2执行 · 关节输出力矩给了不该给的：力矩或角度超出安全限幅，造成拉伤或关节过载。硬件限幅，越限即切断助力输出（SSR-1）。
UCA-6监护 · 越界处置该给没给：越界了没识别、没告警、没切断，患者继续承受增强输出。监护独立自检、失效显性告警（SSR-4 / SSR-8）。
UCA-11人在环 · 退出请求该给没给：退出或急停请求被拒绝、被延迟，患者无法终止助力。人工否决权最高、硬线直达（SSR-6 / SSR-10）。

追踪结果

十二条功能需求全部能落到六个系统与十九个子系统上；七条性能需求中，PR-1、PR-3、PR-5、PR-7 直接派生自安全约束，其余三条来自训练效果；十二条安全需求覆盖四类不安全控制动作，且每条都指向具体组件。未落地的条目为零，未追溯的组件为零。

尚未完成的部分：以上均为方案层面的推演。没有样机，因此 PR-5 的 8 h 与 PR-7 的切换时间尚未实测；STPA 的失效路径也未做故障注入验证。
