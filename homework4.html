人机混合神经闭环系统
场景分层与运行设计条件

系统不是悬在空中运行的：它嵌在家庭、社区与医院三类环境里，由不同状态的人操作。本页把环境切成四层场景，逐层梳理要素，定出正常运行的设计条件，再取居家独立训练这一个典型场景展开到秒级，并对它做安全风险分析，得到风险场景列表。

依据、对象与做法

作业 1 给出六层分解与第四层的系统边界；作业 2 给出 ENV-1～ENV-4 四类环境、S1～S6 六个运营场景、M0～M7 八个运行模式与人员角色；作业 3 给出 22 条系统需求、六个子系统与安全需求。本页在这三者之上做"环境—场景"这一维度的展开，不重复定义系统功能。

四步做法

① 场景分层：按时间尺度与决策主体，把系统所处环境切成四层；② 逐层梳理要素：每层用同一套十类要素填满，避免只写故事不写条件；③ 定运行设计条件：把"正常"写成可判定的范围，包括环境范围、系统状态、人员状态；④ 取一个典型场景详述，并对它做安全风险分析。

为什么先分层

同一个系统，在"机构采购与支付政策"层里的约束和在"一次 50 ms 闭环"层里的约束完全不同。不分层就会把政策问题写成技术指标，或把毫秒级失效说成流程问题。分层之后，每层的判据、责任人和可改动的自由度都是清楚的。

术语：SL = 场景层（Scenario Layer）· RDL = 运行设计范围（Run Design Limits）· CA = 控制动作（Control Action）· UCA = 不安全控制行为（Unsafe Control Action）· RS = 风险场景（Risk Scenario）。

01

场景分层

四层由外向内：环境层决定"允许在什么条件下用"，使命层决定"为什么用、谁组织"，运行层决定"一次使用怎么走"，交互层决定"毫秒之间怎么配合"。上层给下层设约束，下层向上层反馈证据。

4.2 失败分支

分支 a：阻抗超限（T0/T1）

连续 2 次提示重戴仍超限 → 保持 M3 监护，不进入 M4；向患者说明"今天只能记录、不能辅助"；记录事件；若照护者在场可协助重戴后再自检。关联 FR-01 / HZ-03。

分支 b：网络与云端不可用（T3/T8/T9）

处方已在本地缓存 → 正常训练；摘要在本地生成并排队；恢复后自动补传，按时间戳去重；不因云端不可用而阻断训练。关联 FR-10 / IR-04。

分支 c：训练中出现异常（T5/T7）

患者感到疼痛或设备异响 → 按急停（或系统过流判定）→ M6，硬件切断 ≤10 ms，保留采集与告警；需人工复位并重跑自检；事件包推送配偶手机。关联 FR-12 / SR-01 / FR-08。

分支 d：低电量（T9 前）

电量 <15% → 限幅并提示；<5% → 有序关机（先撤力再断电），禁止直接断电导致突然失去支撑。关联 PR-06 / SR-06。

4.3 这个场景说明了什么

  • 自立性设计：T1 与 T2 合起来必须 ≤5 min，否则居家频次无法维持；界面不能假设有专业人员解读。
  • 弱网自治：处方、摘要、事件三类数据都要能本地闭环，云端只做旁路同步——这正是作业 3 CN-03 的由来。
  • 无人监督的安全边界：患者是唯一能按急停的人，所以急停必须是物理可达、硬件常闭、不依赖软件与网络。
  • 降级而非停机：T7 的限幅让训练继续，比一刀切停机更符合"安全 vs 可用"的权衡（C-3）。
05

典型场景的安全风险分析

用系统理论过程分析（STPA）的做法：先定损失与危险，再逐个控制动作问"没给 / 给错 / 给太久 / 给太早"四类不安全行为，最后落到风险场景列表与控制措施。它比逐部件 FMEA 更能抓到"人—机—环境配合错位"这一类失效。

5 项高风险全部指向同一类失效：系统在"该降级/该告知"的时候保持了沉默。因此在作业 3 的 SR-06 之外，本页补出一条设计原则——降级必须可见、可感知、可取消，静默降级视为安全缺陷。

追踪与结论

6.1 场景层与需求对照

场景层由谁来判定"正常"落到哪些需求失效时的处置
SL-1 环境机构 / 监管 / 采购CN-01、CN-02、PR-06、IR-07暂停使用或改配置档位
SL-2 使命治疗师 / 机构管理员FR-06、FR-07、FR-09、BR-01、BR-06退回上一版处方与服务流程
SL-3 运行患者 / 照护者FR-05、FR-10、FR-12、PR-05、SR-06/07进入 M5 降级或 M6 急停
SL-4 交互系统控制器（人监督）FR-02、FR-03、PR-01、SR-01/02限幅 → 撤力 → 切断

6.2 结论

  • 系统所处的环境可以切成四层，每层的"正常运行"由不同主体判定；把它们混在一起谈，是需求失真的主要来源。
  • 居家独立训练是典型场景：频次最高、专业支持最少、环境最不可控，因此它同时决定了自立性（≤5 min）、弱网自治（24 h）与安全边界（硬件急停）三条要求。
  • 经 STPA，12 个风险场景中 5 个为高风险，全部落在"该降级却沉默"这一模式上；对应措施已回填为可验证的约束，可直接进入下一轮设计与验证。
  • 遗留：多场景（社区集体训练、夜间独处、外出使用）尚未逐场分析；RS-05 的 24 h 回路自检需与硬件设计确认可行性。
