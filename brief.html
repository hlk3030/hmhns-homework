系统需求规格书与初始架构

原版 →

把 BR / StR 落成 22 条系统需求（12 功能 + 10 性能），另有 8 条接口需求与 5 条约束；六子系统架构 + 50 ms 闭环 + 10 条安全需求。

子系统职责关键接口
A 采集电极、AFE、阻抗监测、运动伪迹抑制向 B 输出采样流；阻抗超标信号给 F
B 解码特征提取、意图分类、置信度评估向 C 下达辅助指令；置信度给 F

E 通信BLE / Wi-Fi / 4G、缓存补传向云端同步；断网本地闭环
F 安全急停、看门狗、越限判定、事件记录独立硬件通道，可切断 C 的动力回路

安全设计的骨架是两层隔离：软件层（越限判定 + 限幅 + 分级告警）与硬件层（独立急停回路 + 看门狗），后者不依赖前者的正确性。

04

场景分层与运行设计条件

原版 →

把环境切成四层，每层十类要素（共 40 项）；把"正常"定成可判定范围，再用居家独立训练这个典型场景检验安全设计。

场景层 · 尺度决策主体本层要素要点
SL-1 环境
年—月		机构 / 监管温湿度 10–30 ℃、湿度 20–80%、噪声 ≤70 dB、供电与网络覆盖、器械与支付政策
SL-2 使命
周—月		医院 / 社区三级连续照护流程、处方权归属、周训练 ≥3 次、4 周复评节点
SL-3 运行
小时		患者 / 照护者一次会期 ≤60 min、单日佩戴 ≤8 h、八状态 M0–M7 与迁移、降级与急停处置
SL-4 交互
毫秒—秒		系统控制器四类控制动作（提供辅助 / 切断 / 降级 / 告警）、硬限幅 120%、误输出 ≤1 次/h

典型场景 S2（居家晚间独立训练）：T0 自检 → T1 佩戴（≤2 min）→ T2 标定 → T3 加载处方 → T4–T6 三组训练（渐入 300 ms、撤力斜坡）→ T7 低置信度降为限幅 → T8 摘要 ≤5 min 生成、弱网缓存 → T9 卸下记录。关键判据：准备 ≤5 min、摘要在本地闭环、患者是唯一能按急停的人。

经 STPA 得 12 个风险场景（5 项高风险：量级误判、超时仍输出、急停回路失效、长时间低置信度仍全量输出、告警错送达），均指向同一失效模式——该降级时保持了沉默；据此补一条原则：降级必须可见、可感知、可取消。
